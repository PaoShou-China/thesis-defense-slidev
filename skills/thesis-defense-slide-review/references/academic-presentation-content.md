# 学术演示教程：内容要求与审查判据

核验日期：2026-10-19。以下为对机构原始教程的中文归纳和工科答辩适配，不是学校强制规范，也不代表对这些做法具有普遍效果的保证。

## 来源

- S1 [MIT NSE：Structuring a Slide Presentation](https://mitcommlab.mit.edu/nse/commkit/structuring-a-slide-presentation/)：受众、核心信息、由结果反推叙事、标题故事线。
- S2 [MIT Mechanical Engineering：Technical Presentation](https://mitcommlab.mit.edu/meche/commkit/technical-presentation/)：单页观点、方法取舍、结果读法、提问与过渡。
- S3 [MIT AeroAstro：Slide Design](https://mitcommlab.mit.edu/aeroastro/commkit/slide-design/)：页面信息与主旨的关系、科研图表适配、视觉层级。该教程明确以设计为主，不能作为全篇内容结构要求的唯一依据。
- S4 [Penn State：EA Guide for Assertion-Evidence Presentations](https://writing.engr.psu.edu/assertion_evidence_EA.html)：先写核心信息，用视觉证据支撑，次要细节放备注。
- S5 [CMU Libraries：PhD Dissertation Defense Slides Design](https://guides.library.cmu.edu/c.php?g=883178&p=6345731)：研究重要性、本人贡献、多项目联系、过渡、备份页与演练。
- S6 [CMU Libraries：Presentation Checklist](https://guides.library.cmu.edu/c.php?g=883178&p=6377846)：重要性、贡献、资助致谢、图表字号与页码。

## 可执行的内容判据

| 内容要求 | 审查动作 | 不满足时怎么改 | 来源 |
| --- | --- | --- | --- |
| 先确定受众与核心信息 | 从全文提取一句希望听众记住的话，检查技术深度与听众背景是否匹配 | 收窄主张，补足必要前提，删除不服务于主线的信息 | S1 |
| 从实际结果反推能讲的故事 | 将主要结论逐项关联到结果，再决定方法和背景篇幅 | 先确定证据支持什么，再组织讲述顺序 | S1 |
| 只看标题也能理解推进关系 | 单独连读所有内容页标题，标记重复、跳步和空泛标题 | 将标题改成明确的问题、回答或发现 | S1、S4 |
| 每页围绕一个主要观点 | 用一句话概括本页，检查是否存在互不依赖的多个结论 | 拆页或将次要内容移入备注 | S2、S3 |
| 页面正文直接支持主旨 | 逐一说明图、公式、文字与本页主旨的关系 | 删除装饰材料，增加直接证据或限定结论 | S3、S4 |
| 方法解释服务于结果理解 | 判断每个方法细节是否影响听众理解证据、贡献或假设 | 主讲保留关键机制，将次要实现细节放备份页 | S1、S2 |
| 先让听众知道怎样读图 | 检查变量、坐标、单位、对照和关注信号是否已说明 | 在展示结果前后明确读图任务与判断依据 | S2 |
| 将论文图表改造成演示图表 | 检查多子图、小字号与无关曲线是否分散注意力 | 放大关键部分并补充标注，保留解释结论所必需的信息 | S3 |
| 研究重要性落到实际问题 | 检查现有做法的不足、受影响任务和解决后的价值 | 用具体场景说明动机，避免只有宏观口号 | S5 |
| 本人贡献与已有工作可区分 | 找出论文沿用的基础与本人新增的部分 | 在引言和对应研究部分明确归属 | S5 |
| 多项工作组成整体 | 检查项目间是否共享目标或存在明确依赖 | 用总体路线图说明联系；只有并列关系时如实说明 | S5 |
| 章节过渡交代承接关系 | 检查是否说明上一部分解决了什么、下一部分为何必要 | 补一句连接研究问题的过渡，必要时重访路线图 | S2、S5 |
| 细节进入可检索的备份页 | 检查长推导和大表是否挤占主讲时间 | 按潜在问题组织备份材料并设置清晰标题 | S5 |
| 演练验证理解与时长 | 请同领域和非同领域听众复述核心信息，记录卡点与用时 | 针对无法复述之处重写，并调整内容取舍 | S5 |
| 收尾明确重要性与贡献 | 检查最终总结是否回答研究价值、本人贡献及必要致谢 | 用真实证据收束贡献，按实际情况注明资助 | S6 |

## 工科博士答辩适配

以下为基于上述教程形成的操作建议，不逐字归属于任何单一来源：

1. 对每项研究建立“具体问题—关键机制—理论或实验依据—发现—边界”对应表。
2. 讲清关键假设、稳定性或可行性条件、参数与基线选择；不以减少文字为理由删掉决定结论成立的条件。
3. 指标提升须附工况、基准、单位与统计口径，区分现象、解释和已证明机制。
4. 为主要结论保留真实局限；不通过删掉失败工况、对照或不确定性制造优势。
5. 内容页标题优先表达观点，但目录、封面、问题定义页可使用功能性标题。领域习惯允许短语标题，不机械要求每页完整句。
6. 不把教程中的页数、分钟数或最低字号推广为通用规定；按答辩要求、内容复杂度和实测讲述时间取舍。
7. 自说明以读者能辨认问题、证据和结论为目标，不把逐字讲稿塞进页面；详细解释用备注或补充材料。

## 页面修改示例

- 原标题“实验结果” → “在给定扰动工况下，方法降低了跟踪误差”（仅当结果真实支持时使用）。
- 原页面同时放算法推导、平台照片和三组曲线 → 分成“关键机制”和“验证结果”，照片只在解释实验条件时保留。
- 原章节之间只有“研究内容二” → 补充“上一部分获得模型；下一部分研究如何在计算约束下利用模型”，前提是两项工作确有这一联系。
